# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Lexicon: a vocabulary flashcard web app built with React 18 and Firebase (Auth + Firestore). Most UI strings and many code comments are in Russian.

## Running

- `npm start` (or `npm run dev`) serves the repo root with `python3 -m http.server 3000`. Open http://localhost:3000.
- There is **no build step, bundler, linter or test suite**. `@babel/*` in `package.json` is unused at runtime.
- Deploy Firestore rules with `firebase deploy --only firestore:rules` (`firebase.json` only configures rules).
- `scripts/migrate-uid.mjs` is a one-off Node admin script built on `firebase-admin`. It moves a user's data from one uid to another and is a dry run unless you pass `--apply`. `firebase-admin` is installed in `node_modules` but is missing from `package.json`.

## Architecture

**In-browser JSX, shared global scope.** `index.html` loads React and ReactDOM (UMD), `@babel/standalone` and the Firebase **compat** SDK (v10) from CDNs. It then loads the app files as `<script type="text/babel">` in this fixed order:

`firebase.jsx` → `data.jsx` → `progress.jsx` → `reading.jsx` → `components.jsx` → `auth.jsx` → `app.jsx`

- None of these files use `import`/`export`. Each one publishes its API with `Object.assign(window, {...})` at the bottom, and later files use those globals (often as `window.lwX`). A new file must be added to `index.html` in the correct position. A function used by another file must be added to that file's `Object.assign(window, …)` list.
- Naming convention: globals use the `lw` prefix for functions (`lwSetDoc`) and `LW_` for constants (`LW_KEYS`). React components use PascalCase.
- **All CSS** (design tokens on `:root`, the dark theme via `html[data-theme="dark"]`, and every component style) lives in the `<style>` block of `index.html`. No CSS files exist.
- **Design system: "Lucid Mentor"** (`stitch_/lingoflow/DESIGN.md`). Tokens are named after it: `--surface` (page background), `--surface-low`, `--surface-lowest` (cards), `--surface-high`/`--surface-highest`, `--on-surface`, `--on-surface-variant`, `--primary` (blue), `--secondary` (gold, used for correct/success), `--tertiary` (progress bars), `--error`. Fonts are Plus Jakarta Sans (`--font-display`) and Inter (`--font-body`). Follow the "no-line" rule: separate areas with background shifts and shadows, not 1px borders. Where a boundary is needed, use `var(--ghost)`. `DESIGN.md` defines no dark theme, so the dark values in `index.html` are our own. UI text is English.

**File responsibilities**
- `firebase.jsx` is the only place that talks to Firestore and Auth. It holds the config, register/login (username or email), account deletion, the live `onSnapshot` watchers, `lwSetDoc`/`lwDeleteDoc`, and the admin fetches.
- `data.jsx` holds device-local state. That covers the `LW_KEYS` localStorage keys with the `lwLoad`/`lwSave` helpers, photo resize and auto-lookup (Openverse, then Wikipedia), and the Gemini AI calls (`lwAiFillWord`, `lwAiFillWords`, `lwAiGenerateBatch`).
- `progress.jsx` holds pure spaced-repetition logic with no Firestore or React: the Leitner boxes (`LW_BOXES`: 10 min, 1 d, 3 d, 7 d, 14 d, 30 d; box 5 means Mastered), `lwNextProgress`, `lwWordStatus`, streak, XP and level.
- `reading.jsx` holds pure text helpers for the reader: Gutenberg cleanup (`lwCleanGutenberg`), chapter detection (`lwSplitChapters`: numbered or roman headings, else table-of-contents titles, else ~1500-word parts), pages (`lwPaginate`), sentences, tokens, and matching tapped tokens to the user's words (`lwWordsIndex`/`lwMatchOwnWord`). It also finds phrase cards for a collocation (`lwFindPhraseCards`) and builds default chip text (`lwCollocPartner`).
- `components.jsx` contains shared UI: icons (`Ic`), `Flashcard`/`FillCard`, `Modal`, `WordForm`, `ImportView`, `GeminiKeyModal`, `CollocForm` (create/edit a collocation), and for grammar `Marked` (renders `[[highlight]]` markup), `LessonBody` (the lesson content, also used by the editor preview) and `LessonForm` (the admin lesson editor).
- `auth.jsx` contains `AuthView`.
- `app.jsx` holds the root `App`, the shell (`AppBar`, `NavDrawer`, `TabBar`) and all page views (`LearnView` wrapping Study/Review/Choice/Fill, Reading, Library, Import, Profile, Admin). Library has a Words view (status chips, group filter, sort, word of the day kept stable per day in `LW_KEYS.wotd`, AI part-of-speech tagging) a Groups view (the group tree) and a Collocations view (`CollocCatalog`, `CollocSheet`). `CategoryView` is the group picker, shown in a bottom sheet (`<Modal sheet>`). It also mounts React.
- Grammar (`GrammarScreen` in `app.jsx`) has a lesson list by topic (`GrammarHome`), the lesson (`LessonView`), its test (`LessonQuiz`) and, for admins, the editor page.
- Navigation state is `nav = {tab, learnMode, reading, grammar}`, persisted in `LW_KEYS.nav`. Tabs are `learn | reading | grammar | library | profile | import | admin`, and Learn modes are `cards | review | choice | fill | colloc` (Phrases, the collocation game `CollocView`). Navigate with `goTo(name)`, which also accepts Learn modes, the legacy `'study'`, `'category'` (opens the group sheet) and `'collocations'` (Library → Collocations). Toast actions use these names. Below 1024px the UI is an app bar, a slide-in drawer and a bottom tab bar. From 1024px the drawer becomes a permanent sidebar.

**Data model (Firestore)**
- `users/{uid}` stores `{username, role: 'user'|'premium'|'admin', langs, lang, createdAt}` plus optional `dailyGoal`, `cefr`, `cefrTarget` (English; other languages use `cefr_<code>`/`cefrTarget_<code>`, see `lwCefrField`) and `avatar` (a 256px JPEG data URL, under 200 KB by rule). Update your own fields with `lwUpdateUser`, never by rewriting the whole doc. `usernames/{lowercased}` stores `{uid}` and enforces unique usernames.
- **Languages**: English (`en`) and Romanian (`ro`), listed in `LW_LANGUAGES` (`data.jsx`) with the Russian word forms used in Gemini prompts, the speech tag and the Wikipedia edition. `users.langs` lists the languages a user learns (picked after sign-up in `LanguageSelectView`, one or both) and `users.lang` is the one studied now (older profiles have only `lang`; `lwUserLangs` normalises). Groups, words, collocations, texts and lessons carry `lang`, and docs without it are English (`lwDocLang`). Firestore queries are unchanged: `App` filters every collection to the current language client-side (`scopedGroups`, `scopedWords`, `scopedTexts`, `scopedCollocations`, `scopedLessons`). `App` calls `lwSetCurrentLang` while rendering, so AI prompts, speech (`lwLangVoices`, `lwUtterance`, SpeechRecognition), tokenising/stemming in `reading.jsx` (`LW_LETTERS`, `lwRoStem`) and `lwSetDoc`/`lwSaveText` (which tag a new doc with the current language) follow it without extra arguments. Each language is a separate learner: activity docs are per language (see below), so XP, level, streak, practice time, the week chart and due/status counts cover only the current language. Per-language profile fields use `lwLangField(base, lang)` (`dailyGoal`, `cefr`, `cefrTarget` for English, `<field>_ro` for Romanian); badges earned must be stored the same way. Word, lesson and reading progress are naturally separate because their docs are. Study-group selection (`LW_KEYS.selected` as `{lang: ids}`), card direction (`LW_KEYS.direction` as `{lang: 'en-ru'|'ru-en'}`, meaning studied language → Russian or back), AI reading cards (one localStorage key per language) and the chosen voice are per language too. `<main>` is keyed by language, so views remount on a switch (Profile, or the switcher in the drawer).
- Words may carry `pos` (one of `LW_POS`, filled by Gemini or by hand) and `createdAt` (ms, only on words added since stage 4). `lwSetDoc` replaces the whole doc, so edits must start from the stored doc. `WordForm` spreads `initial` for this reason.
- `groups` and `words` are flat collections. Every doc has `userId`, `username` and `shared`. Groups nest one level deep through `parentId`. Words belong to a group through `groupId`, and only leaf groups (`lwLeafGroups`) can hold words.
- Clients see their own docs **plus** docs with `shared: true`; `lwWatchUserAndSharedCollection` merges the two queries. Only admins can create shared docs, and anything an admin creates or imports is written with `shared: true`.
- `firestore.rules` enforces this. `list` queries must carry filters (`userId == uid` or `shared == true`) that prove every result is allowed, so new queries need those filters too. One example is the extra `userId` filter in `lwDeleteWordsByGroup` for non-admins. `lwSetDoc` strips `undefined` fields because Firestore rejects them.
- Legacy accounts sign in with a synthetic email `<username>@lexicon.local`. Newer accounts use real emails or Google (`lwSignInWithGoogle`). A first Google sign-in has no `users` doc, so `App` shows `ChooseUsernameView` (`lwCreateProfile`). `lwWatchUserDoc` reports `null` (no profile) only from the server, never from the offline cache, and `userDoc` is `undefined` while it loads. Google can be linked or unlinked in Profile, and account deletion re-authenticates with the password or a Google popup.
- Firestore runs with `enablePersistence` (offline cache, synced tabs). The app keeps working if the network drops, but it cannot cold-start offline because there is no service worker.
- `progress/{uid}_{wordId}` stores `{userId, wordId, box, due, reps, lapses, lastSeen, lastMode}`, one doc per user per word. It sits in a separate collection because users can't write shared words. `activity/{uid}_{YYYY-MM-DD}` for English and `activity/{uid}_{lang}_{YYYY-MM-DD}` for other languages (device-local date, `lwActivityRef`) store `{userId, lang, date, answers, correct, xp, goalMet, ms}`; the rules accept both id forms. Both are written together by `lwRecordAnswer` (one batch, `merge` + `increment`, no transaction). Total XP is the sum of `activity.xp` of the current language. The daily goal is `users/{uid}.dailyGoal` (`dailyGoal_ro` for Romanian), default 20 answers.
- Reading texts: `texts/{id}` holds the meta (`title, author, level, source, chapters: [{title, words}], wordCount`, plus `userId/shared` like words, and only admins publish `shared` books). The body is in `texts/{id}/chapters/{n}` as `{userId, shared, title, paragraphs}`, so lists load without text. `reading_progress/{uid}_{textId}` stores `{chapter, page, pct}`. Words added from the reader go to the user's "From reading" group (created on first use) with the book sentence as the example, and they are always private.
- Collocations: `collocations/{id}` stores `{word, key, pos, pattern, phrases: [{wordId, partner}], wrong: [{partner, fix}]}` plus `userId/username/shared` like words. The phrases are ordinary word cards. The entry only links them by id, and `partner` is the chip text in the game. Phrase text, translation and example are always read from the card, so a deleted card drops out of the entry (`lwCollocLive`). New phrases added in the form become cards in the user's auto group "Collocations" (shared for admins, whose entries are shared and link only shared cards). The game (`CollocView`) plays entries with ≥2 live phrases and ≥1 wrong partner (`lwCollocPick`). A right chip is Know for its card, a wrong chip is Again for every right phrase not found yet, and Hint is Again for the hinted one. Each card gets at most one answer per round. Gemini (`lwAiSuggestCollocations`) runs only from the form's "Suggest with AI". `recordAnswer` tracks answers sent today in a ref, so several answers in one tick award the goal bonus once.
- Grammar lessons: `lessons/{id}` are shared content written only by admins: `{title, topic, level, order, minutes, compare, published, focus, formulas, compareTable: {rows, tip}, examples, quiz}`. Text fields use `[[...]]` for highlights. `quiz` always has exactly 10 tasks (`LW_LESSON_TASKS`, enforced by the rules and `lwNormTask`): `{type: 'choice', q, options[4], answer, why}` or `{type: 'fill', q, answers[], why}`. Users read only published lessons (query `published == true`). Admins see drafts. `lesson_progress/{uid}_{lessonId}` stores `{studiedAt, attempts, last, best, completedAt, saved}`. In a topic, lessons are ordered by `order`, and a lesson opens once the previous one is completed (`lwLessonStatus`: locked/new/studied/completed). The test unlocks after "I've studied this". Tasks and options are shuffled per attempt. Only 10/10 completes a lesson and gives a one-time +50 XP (`lwAddBonusXp`). Each test answer goes through `recordAnswer(null, …)`, which writes activity only (`lwRecordAnswer` with `progress: null`). Gemini helpers are `lwAiGenerateLesson` and `lwAiRegenerateTask`. Starter lessons come from `scripts/seed-lessons.mjs`, run from the browser console as an admin.
- Badges: `LW_BADGES` (`progress.jsx`) are 23 achievements (streak, daily goal, answers, words, time, level, reading, grammar, collocations). They are computed on the device from the current language's data (`lwBadgeMetrics`; the streak badge uses the best streak ever, `lwBestStreak`). `App` saves newly reached ones as `users/{uid}.badges.<id> = ms` (`badges_<lang>` for non-English) 2 s after the data settles and shows a toast. The first time, it saves quietly with one summary toast. Earned badges stay earned. `BadgesSection` in Profile shows them.
- Level test: `LevelTestScreen` (screen `leveltest`, opened from the level card in Profile) is one engine for every language. Questions come from `level_questions` (`{lang, level, skill, q, options[4], answer, why}`): shared content that only admins write, edited in-app through `LevelQuestionsAdmin`, with starter banks of 60 per language in `scripts/seed-level-questions.mjs`. The test asks 20 questions on a staircase (`lwLevelTestPick`): right moves one level up, wrong or "I don't know" one level down, and no question repeats. The result (`lwLevelTestResult`) is the rounded mean staircase step of the last 10 answers, one step lower if fewer than half at that level were right. It is saved as `users.levelTest` (`levelTest_<lang>`) and, if the user agrees, as their CEFR level. It gives no XP. The test is offered once a language has at least 30 questions.
- Speech: every spoken text goes through `lwUtterance(text, rateMul)` in `data.jsx`, used by `lwSpeak` and the reader's read-aloud. It uses the device's best voice for the current language (`lwLangVoices`, ranked by `lwVoiceScore`) or the one picked in Profile (`VoicePicker`), plus Slow/Normal speed. Both are stored on the device in `LW_KEYS.voice`. A missing voice falls back to auto. When the device has voices but none for the current language, `lwUtterance` dispatches `lw-missing-voice` and `App` shows a toast once per language and session (otherwise the browser silently reads with its default English voice).
- Romanian transcription: `lwRoIpa(text, pos)` (`data.jsx`) builds a broad IPA transcription by spelling rules, without stress. `lwSetDoc` fills `ipa` with it for any Romanian word saved without one.
- Pronunciation: `PronunciationCheck` (components.jsx) uses the browser's SpeechRecognition and is hidden when the browser doesn't support it. It compares the transcript with the target text by longest common subsequence (`lwMatchSpoken`). Reading time goes into `activity.ms` through `lwAddPracticeTime`, every 30 s while a text is open, the page is visible and the user was active in the last minute. It adds no answers or XP.
- The rules define an `ai_usage` collection meant to be written by a Cloud Function, but no functions code exists in this repo.

**State flow in `App`**
- Auth state → user doc → live subscriptions to groups and words. All data lives in `App` state and reaches the views as props.
- `App` also subscribes to `progress` and `activity` and owns `recordAnswer(wordId, known, mode)`. Study, Fill, Choice and Review call it on every answer except skip. Know only moves a word up a box once it is due, so reviewing early keeps the box. Review (`ReviewView`) queues every word whose `due` has passed, across all groups.
- Device-only settings (theme, selected groups, study direction, last batch of reading cards, the user's **personal Gemini API key**) persist in localStorage under the versioned `lw_*_v1` keys.
- Long-running AI jobs (reading-text generation, AI fill on import) run as promises owned by `App` (`startReadingGeneration`, `startImportAiFill`), so they survive tab switches. Results come back as toasts. `genIdRef` discards stale responses.
- Gemini is called straight from the browser with the user's own key. AI helpers throw errors whose `.code` is `no-key`, `bad-key`, `quota`, `refusal` or `network`, and `app.jsx` maps those codes to messages (`LW_READING_ERROR_MSG`, `LW_IMPORT_ERROR_MSG`).
