# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Lexicon: a vocabulary flashcard web app built with React 18 and Firebase (Auth + Firestore). Most UI strings and many code comments are in Russian.

## Running

- `npm install` once, then `npm start` (or `npm run dev`) runs the Vite dev server on http://localhost:3000. `npm run build` writes a static site to `dist/` (relative paths, `base: './'`), and `npm run preview` serves it. React, ReactDOM and Firebase come from npm (`package.json`), not CDNs.
- `npm test` runs the Vitest suite in `test/` (Node, UTC, `test/setup.ts` gives the modules a `window`): FSRS against reference values from ts-fsrs 5, the Review queue, streaks, lessons and their review queue, the level test, collocations, word forms, navigation and the reader's text helpers. `npm run typecheck` runs `tsc` (TypeScript 7) over the `.ts` files. There is no linter.
- The live site is GitHub Pages. `.github/workflows/pages.yml` runs `npm ci`, `npm run typecheck`, `npm test` and `npm run build` on every push to `main` (a failure stops the deploy) and publishes `dist/` (Pages source: GitHub Actions), so a push to `main` is a deploy.
- Deploy Firestore rules with `firebase deploy --only firestore:rules` and composite indexes (`firestore.indexes.json`: `progress (userId, updatedAt)`, `activity (userId, updatedAt)`, `lessons (published, lang, updatedAt)` and `lessons (lang, updatedAt)`) with `firebase deploy --only firestore:indexes`.
- `scripts/check-words.mjs` is a read-only `firebase-admin` script. It reports which candidate words (from stdin) a user already sees in a language (`--user <username> --lang en|ro`). The `add-words` skill (`.claude/skills/add-words/`) uses it to prepare lines for Import without duplicates.
- `scripts/check-words.mjs --words "<group>[,<group>]"` dumps the words of those groups as JSON. The `make-book` skill (`.claude/skills/make-book/`, `/make-book`) uses it to write a reading book from a params file in `books/inbox/` (format in `books/README.md`) into `books/ready/<slug>.mjs`. `scripts/check-book.mjs <file>` checks a book offline: coverage of `BOOK.targets` (with the reader's own matching, imported from `reading.ts`; Node strips the types itself) and exercise errors. The book file calls `uploadBook` from `scripts/upload-book.mjs`, so it is uploaded with `await import('/books/ready/<slug>.mjs')` in the browser console on the dev server (`books/` and `scripts/` are not part of `dist/`) (admin → shared Books; `replace: true` rewrites a book with the same title under the same id). `books/example.mjs` is a one-chapter sample.
- `scripts/db-size.mjs` is a read-only `firebase-admin` script. It estimates Firestore storage per collection (data plus a rough upper bound for indexes), how many more average docs or books fit in the quota (`--limit` in MiB, default 1024), and size per owner. A full run costs one read per document, and `--count` only counts documents (cheap).
- `scripts/migrate-uid.mjs` is a one-off Node admin script built on `firebase-admin`. It moves a user's data from one uid to another and is a dry run unless you pass `--apply`. `firebase-admin` is a devDependency.

## Architecture

**Vite + ES modules.** `index.html` loads one entry, `<script type="module" src="/app.jsx">`, and Vite (`vite.config.js`, `@vitejs/plugin-react`) bundles the rest through imports. Files without JSX are `.js` or `.ts`, so Node scripts can import them too. TypeScript is being adopted file by file: the pure logic is `.ts`, the rest is still JS/JSX:

`firebase.js` (+ `firebase-console.js`, `idb-cache.js`) · `data.js` · `wordsync.ts` · `deltasync.ts` · `progress.ts` · `reading.ts` · `forms.ts` · `nav.ts` · `types.ts` · `components.jsx` · `auth.jsx` · `views/*.jsx` · `app.jsx`

- Each file ends with `export { … }` and imports what it uses from the others (`import { lwSetDoc } from './firebase.js'`). There are import cycles (`firebase` ↔ `data` ↔ `reading`). They are safe because no top-level code calls into another file while modules load, so keep it that way: cross-file calls belong inside functions.
- Firebase is the **modular** SDK (v10): `firebase.js` imports functions from `firebase/app`, `firebase/auth` and `firebase/firestore` (`getDoc`, `setDoc`, `query`, `where`, `onSnapshot`, `writeBatch`…) and builds references with its local helpers `col(...path)` and `ref(...path)`. The offline cache is `initializeFirestore` with `persistentLocalCache` + `persistentMultipleTabManager`.
- After its `export` list each file also runs `Object.assign(window, {...})`. That is only a **console API**: `scripts/*.mjs` and the book files are pasted or imported in the browser console and call `window.lwX` and `window.firebase`. The latter is not the real SDK but a compat-style shim (`firebase-console.js`: `auth().currentUser`, `firestore().collection().doc()/where()/get()/set()/update()/delete()`, `batch()`) over the modular one; extend it if a console script needs more. App code must use imports, not `window.lwX`. Add a function to the `window` list only when a console script needs it.
- **TypeScript** (`tsconfig.json`): `strict`, `noEmit`, `erasableSyntaxOnly` (types only, no enums or namespaces, so Node can run the files too) and `allowImportingTsExtensions`: import TS files with their extension (`./progress.ts`). Type-only imports use `import type`. `types.ts` describes the Firestore docs (`Word`, `Group`, `Progress`, `Activity`, `UserDoc`, `Text`, `Chapter`, `Collocation`, `Lesson`, `LevelQuestion`, `Clip`…); keep it in step with the data model below. JS files are read for their inferred types but not checked (`checkJs: false`). To move a file to TS: `git mv` it to `.ts`/`.tsx`, update the imports that name it, add types until `npm run typecheck` passes, and keep `npm test` green.
- `index.html` keeps a small inline startup watchdog (shows errors if the app never mounts). `LwErrorBoundary` calls its `window.lwRenderFatal(error, React.createElement)`.
- Naming convention: globals use the `lw` prefix for functions (`lwSetDoc`) and `LW_` for constants (`LW_KEYS`). React components use PascalCase.
- **CSS** lives in `styles/`: `index.html` links `styles/main.css`, which `@import`s the area files in the original cascade order (`tokens.css` with the design tokens on `:root`, the dark theme via `html[data-theme="dark"]` and base styles, then `shell`, `learn`, `profile`, `library-words`, `reading`, `widgets`, `cards`, `controls`, `responsive`, `collocations`, `grammar`, `extras`). Keep that order; add a rule to the file of its area. Vite bundles the CSS into one file but does not minify it (`cssMinify: false`), because the minifier drops fallbacks such as `overflow-x: hidden` before `clip` and `-webkit-backface-visibility` (card flip on older Safari).
- **Design system: "Lucid Mentor"** (`stitch_/lingoflow/DESIGN.md`). Tokens are named after it: `--surface` (page background), `--surface-low`, `--surface-lowest` (cards), `--surface-high`/`--surface-highest`, `--on-surface`, `--on-surface-variant`, `--primary` (blue), `--secondary` (gold, used for correct/success), `--tertiary` (progress bars), `--error`. Fonts are Plus Jakarta Sans (`--font-display`) and Inter (`--font-body`). Follow the "no-line" rule: separate areas with background shifts and shadows, not 1px borders. Where a boundary is needed, use `var(--ghost)`. `DESIGN.md` defines no dark theme, so the dark values in `index.html` are our own. UI text is English.

**File responsibilities**
- `firebase.js` is the only place that talks to Firestore and Auth. It holds the config, register/login (username or email), account deletion, the live `onSnapshot` watchers, `lwSetDoc`/`lwDeleteDoc`, and the admin fetches.
- `data.js` holds device-local state. That covers the `LW_KEYS` localStorage keys with the `lwLoad`/`lwSave` helpers, photo resize and auto-lookup (Openverse, then Wikipedia), and the Gemini AI calls (`lwAiFillWord`, `lwAiFillWords`, `lwAiGenerateBatch`).
- `progress.ts` holds pure spaced-repetition logic with no Firestore or React: the FSRS-6 scheduler (formulas and default weights `LW_FSRS_W` from ts-fsrs 5, written out by hand, no library), `lwNextProgress`, `lwWordStatus`, `lwWordMastery`, the Review queue (`lwReviewQueue`, `lwGroupPaused`), streak, XP and level.
- `forms.ts` holds pure helpers for a word's principal forms (see Data model): the slots per language and part of speech (`LW_FORM_SLOTS`, `lwFormSlots`), normalising (`lwNormForms`), the Import column (`lwFormsToText`/`lwParseFormsText`), the card label (`lwFormsLabel`), the drill prompts (`lwFormPrompts`), the Forms deck (`lwFormsDeck`) and the Gemini prompt part and schema (`LW_FORMS_AI_HINT`, `LW_FORMS_AI_SCHEMA`).
- `reading.ts` holds pure text helpers for the reader: Gutenberg cleanup (`lwCleanGutenberg`), chapter detection (`lwSplitChapters`: numbered or roman headings, else table-of-contents titles, else ~1500-word parts), pages (`lwPaginate`), sentences, tokens, and matching tapped tokens to the user's words (`lwWordsIndex`/`lwMatchOwnWord`). It also finds phrase cards for a collocation (`lwFindPhraseCards`) and builds default chip text (`lwCollocPartner`).
- `components.jsx` contains shared UI: icons (`Ic`), `Flashcard`, `FillCard` (the word is typed into the blank: right = Know, after "Show answer" = Again; no Again/Know buttons; the corner lightbulb flips the card to the sentence translation; typed right within 12 s with no wrong Enter and no look at the translation = Easy), `Modal`, `WordForm`, `GeminiKeyModal`, `CollocForm` (create/edit a collocation), and for grammar `Marked` (renders `[[highlight]]` markup), `LessonBody` (the lesson content, also used by the preview of the admin editor `LessonForm` in `views/lesson-form.jsx`). Import (`ImportView`) is in `views/import.jsx`.
- `auth.jsx` contains `AuthView`.
- `app.jsx` holds the root `App` (auth → profile → data subscriptions, `nav`, `recordAnswer`, toasts, AI jobs) and mounts React. The screens are in `views/`:
  - `shared.jsx`: `shuffle`, error texts (`LW_READING_ERROR_MSG`, `LW_IMPORT_ERROR_MSG`), `AnswerButtons`, `StatusBadge`, auto-group names and `lwLazy`;
  - `shell.jsx`: `AppBar`, `NavDrawer`, `TabBar`, toasts, `CategoryView`, `LanguageSelectView`, `GroupForm`;
  - `learn.jsx`: `LearnView` wrapping Study (Cards), Review, Choice and Fill; `forms.jsx`: `FormsView` (Learn → Forms); `collocations.jsx`: `CollocView` and the Library catalog; `video.jsx` (+ `video-admin.jsx`);
  - `reader.jsx`: Reading home, the reader, `WordSheet`, AI reading cards; `chapter-practice.jsx`;
  - `grammar.jsx` (+ `lesson-form.jsx`); `library.jsx`; `profile.jsx`; `level-test.jsx` (+ `level-admin.jsx`); `admin.jsx`; `import.jsx`.
  - Rare screens load on demand: `lwLazy(() => import('./x.jsx').then((m) => ({ default: m.X })))` gives a component whose file is fetched on first render (a spinner meanwhile). `import.jsx`, `admin.jsx`, `lesson-form.jsx`, `level-admin.jsx` and `video-admin.jsx` are lazy; don't import them statically, or they go back into the main bundle. `vite.config.js` puts `node_modules` (React, Firebase) in a separate `vendor` file that stays cached across deploys.
  - A view file may import from `shared.jsx`, `shell.jsx` and other views, never from `app.jsx`. Keep top-level code free of calls into other view files (they may form import cycles).
- Library has a Words view (status chips, group filter, sort, word of the day kept stable per day in `LW_KEYS.wotd`, AI part-of-speech tagging) a Groups view (the group tree) and a Collocations view (`CollocCatalog`, `CollocSheet`). `CategoryView` is the group picker, shown in a bottom sheet (`<Modal sheet>`). It also mounts React.
- Grammar (`GrammarScreen` in `views/grammar.jsx`) has a lesson list by topic (`GrammarHome`, with the review card on top), the lesson (`LessonView`), its test (`LessonQuiz`), the spaced review of completed lessons (`GrammarReview`) and, for admins, the editor page. The test and the review share `QuizTaskCard`.
- Navigation state is `nav = {tab, learnMode, reading, grammar}` (types, `lwNormNav` and the URL mapping in `nav.ts`), persisted in `LW_KEYS.nav` and mirrored in the URL hash: `#/learn/review`, `#/reading/book/<textId>`, `#/grammar/lesson/<id>/test`, `#/grammar/review`, `#/library`… Every screen change is a history entry, so Back returns to the previous screen, and a link with a hash opens that screen (`lwHashToNav`, falling back to the saved nav). Modals, the drawer and Library's own filters are not in the URL. Tabs are `learn | reading | grammar | library | profile | import | admin`, and Learn modes are `cards | review | choice | fill | forms | colloc | video` (Forms: `FormsView`; Phrases: the collocation game `CollocView`). Navigate with `goTo(name)`, which also accepts Learn modes, the legacy `'study'`, `'category'` (opens the group sheet) and `'collocations'` (Library → Collocations). Toast actions use these names. Below 1024px the UI is an app bar, a slide-in drawer and a bottom tab bar. From 1024px the drawer becomes a permanent sidebar.

**Data model (Firestore)**
- `users/{uid}` stores `{username, role: 'user'|'premium'|'admin', langs, lang, createdAt}` plus optional `dailyGoal`, `cefr`, `cefrTarget` (English; other languages use `cefr_<code>`/`cefrTarget_<code>`, see `lwCefrField`) and `avatar` (a 256px JPEG data URL, under 200 KB by rule). Review settings are `srs: {retention, session, background}` (one set for every language, defaults `LW_SRS_DEFAULTS`, read with `lwSrsSettings`) and paused groups are `groupState: {groupId: 'paused'}` (`groupState_ro` for Romanian; shared groups can be paused too). Update your own fields with `lwUpdateUser`, never by rewriting the whole doc. `usernames/{lowercased}` stores `{uid}` and enforces unique usernames.
- **Languages**: English (`en`) and Romanian (`ro`), listed in `LW_LANGUAGES` (`data.js`) with the Russian word forms used in Gemini prompts, the speech tag and the Wikipedia edition. `users.langs` lists the languages a user learns (picked after sign-up in `LanguageSelectView`, one or both) and `users.lang` is the one studied now (older profiles have only `lang`; `lwUserLangs` normalises). Groups, words, collocations, texts and lessons carry `lang` (`lwSetDoc`/`lwSaveText` add it; `scripts/backfill-lang.mjs`, run in the browser console as an admin (`const bf = await import('/scripts/backfill-lang.mjs'); await bf.count(); await bf.apply()`), counts docs per language and tags old docs without one as `en`). `App` subscribes to these collections for the current language only (`where('lang', '==', lang)` in `lwWatchUserAndSharedCollection` and `lwWatchLessons`; switching language re-subscribes), so a doc written without `lang` is invisible: every write path must set it. `App` still filters client-side (`scopedGroups`, `scopedWords`, `scopedTexts`, `scopedCollocations`, `scopedLessons`, via `lwDocLang`), which covers the moment after a switch when state still holds the old language. Only the current language's groups are loaded, so code must not judge another language's data (e.g. its group selection) by them. Activity, progress and level questions are filtered as before. `App` calls `lwSetCurrentLang` while rendering, so AI prompts, speech (`lwLangVoices`, `lwUtterance`, SpeechRecognition), tokenising/stemming in `reading.ts` (`LW_LETTERS`, `lwRoStem`) and `lwSetDoc`/`lwSaveText` (which tag a new doc with the current language) follow it without extra arguments. Each language is a separate learner: activity docs are per language (see below), so XP, level, streak, practice time, the week chart and due/status counts cover only the current language. Per-language profile fields use `lwLangField(base, lang)` (`dailyGoal`, `cefr`, `cefrTarget` for English, `<field>_ro` for Romanian); badges earned must be stored the same way. Word, lesson and reading progress are naturally separate because their docs are. Study-group selection (`LW_KEYS.selected` as `{lang: ids}`), card direction (`LW_KEYS.direction` as `{lang: 'en-ru'|'ru-en'}`, meaning studied language → Russian or back), AI reading cards (one localStorage key per language) and the chosen voice are per language too. `<main>` is keyed by language, so views remount on a switch (Profile, or the switcher in the drawer).
- Words may carry `pos` (one of `LW_POS`, filled by Gemini or by hand) and `createdAt` (ms, only on words added since stage 4). `lwSetDoc` replaces the whole doc, so edits must start from the stored doc. `WordForm` spreads `initial` for this reason.
- Word forms: verbs, nouns and adjectives may carry `forms`, the principal forms the paradigm follows from and that can't be guessed (`forms.ts`). Romanian only (English has no slots): verb `{pres1, pres3, subj3, part}` (eu lucrez, el lucrează, să lucreze without să, lucrat; a reflexive verb keeps its pronoun), noun `{gender: m|f|n, pl}`, adjective `{f, mpl, fpl}`. An empty `{}` means "checked, none" so Library doesn't offer it again. They come from Gemini (the word and Import fills ask for them; Library's "Fill forms with AI" fills existing words, `lwAiFillForms`), from `WordForm`, or from Import's optional 7th column (comma-separated in slot order: `lucrez, lucrează, lucreze, lucrat`; `f, case`). They show on the back of a card and on Library word cards. Rules that hold for every word (numeral agreement, articles, cases) stay in grammar lessons. Learn shows the Forms mode only when a word of the current language has forms (`lwHasForms`), and Video only when there are clips or the user is an admin (`learnModes` in `App`; a hidden mode in the URL shows Cards). Existing words get forms in bulk with `scripts/fill-forms.mjs`, run in the browser console as an admin: `const ff = await import('/scripts/fill-forms.mjs')`, `await ff.list('verb')` downloads the Romanian words without forms as a text file, `await ff.apply()` shows what `scripts/forms.json` would write and `ff.apply({ write: true })` writes it. Learn → Forms (`FormsView`) drills them: words of the chosen groups whose meaning has been studied (the word has its own progress doc) and whose forms are new or due (`lwFormsDeck`). A word is all its forms in a row as `FillCard`s with a cue (eu ___, el să ___, ___ casă for the gender as un/o, doi/două ___ for the plural). Every typed form is an activity-only answer (`recordAnswer(null, …, 'forms')`); after the last one the forms get one FSRS answer, Know only if all were right (Easy when quick, as in Fill), recorded on the progress doc of `lwFormsId(wordId)` = `<wordId>~forms`. That id fits the progress rules unchanged, and code that walks words looks progress up by word id, so these docs don't count as words. Deleting a word deletes its forms progress too.
- `groups` and `words` are flat collections. Every doc has `userId`, `username` and `shared`. Groups nest one level deep through `parentId`. Words belong to a group through `groupId`, and only leaf groups (`lwLeafGroups`) can hold words.
- **Shared words come from a device cache.** Every page load used to bill all shared words of the language (~2000). Now `lwWatchWords` (`firebase.js`) keeps them in IndexedDB (`idb-cache.js`, key `words:<uid>:<lang>`) grouped by group, and each group has `updatedAt` (server time). `App` passes the shared groups to `syncGroups`, and only groups whose stamp differs from the cached one have their shared words re-read (`groupId == g && shared == true`; a re-read replaces the group, so deletions need nothing extra). The pure logic (plan, cache edits, merge) is `wordsync.ts`. Own words keep a live listener (`words (own)`). So **every write of a shared word must stamp its group**: `lwSetDoc`/`lwDeleteDoc` for words do it (`lwTouchGroups`, collected for 0.5 s into one update per group, also the group a word left), `lwSetDoc` for groups sets `updatedAt`, and console scripts that write words call `window.lwTouchGroups(groupIds)`. A local write shows at once (the watcher patches its cache), and for 15 s after this device stamped a group, a new stamp of that group is taken over without a re-read (`lwAdoptOwnStamps`): it is the device's own edit. As a safety net, a few seconds after load a `count()` of shared words (about 1 read per 1000) is compared with the cache; on a mismatch everything is re-read once and any remaining difference (shared words outside visible groups) is accepted as `countOffset`. A group without `updatedAt` keeps its cached words until it gets one. Firestore rules don't enforce the stamping yet.
- Clients see their own docs **plus** docs with `shared: true`; `lwWatchUserAndSharedCollection` merges the two queries (groups, texts, collocations; words use `lwWatchWords`). For an admin the own query also filters `shared == false`, because the shared query already returns their shared docs and Firestore would bill each one twice. Listeners go through `lwListen` and one-off queries through `lwFetch`, which feed a read meter: run `lwReadReport()` in the browser console to see how many docs each listener got from the server (roughly the billed reads) since page load. Only admins can create shared docs, and anything an admin creates or imports is written with `shared: true`. The exception is Import: while it is open, an admin watches every group and word (`allGroups`/`allWords` in `App`), other users' private groups are shown with the owner's name, and words imported into such a group belong to its owner and are shared like the group (the rules let admins create words for another `userId`).
- `firestore.rules` enforces this. `list` queries must carry filters (`userId == uid` or `shared == true`) that prove every result is allowed, so new queries need those filters too. One example is the extra `userId` filter in `lwDeleteWordsByGroup` for non-admins. `lwSetDoc` strips `undefined` fields because Firestore rejects them.
- Legacy accounts sign in with a synthetic email `<username>@lexicon.local`. Newer accounts use real emails or Google (`lwSignInWithGoogle`). A first Google sign-in has no `users` doc, so `App` shows `ChooseUsernameView` (`lwCreateProfile`). `lwWatchUserDoc` reports `null` (no profile) only from the server, never from the offline cache, and `userDoc` is `undefined` while it loads. Google can be linked or unlinked in Profile, and account deletion re-authenticates with the password or a Google popup.
- Firestore runs with a persistent local cache (offline, synced tabs), so data works without a network. The app is a **PWA** (`vite-plugin-pwa` in `vite.config.js`): a manifest with the icons in `public/` (rendered from the favicon design; the maskable one is full-bleed), and a Workbox service worker that precaches the built files (lazy screens included) and caches Google Fonts, so the installed app cold-starts offline. It is `registerType: 'prompt'`: `App` registers it (`virtual:pwa-register`) and, when a new deploy has downloaded, shows an `info` toast with Reload (`action.run`); until then the old version keeps running, even across plain reloads. The service worker is off in `npm run dev`; test it with `npm run build && npm run preview`.
- `progress/{uid}_{wordId}` stores `{userId, wordId, stability, difficulty, lastReview, due, reps, lapses, lastSeen, lastMode, updatedAt}`, one doc per user per word. `updatedAt` is server time, set by `lwRecordAnswer` (docs from before it have none). `App` gets progress from `lwWatchProgress`, built on **`lwWatchSince`** (`firebase.js`, pure logic in `deltasync.ts`), which also serves activity and lessons: the query's docs are cached in IndexedDB (`progress:<uid>`; `activity:<uid>`; `lessons:all|published:<lang>`) with the latest server `updatedAt` seen, and a load listens only to `updatedAt > that`, which also brings changes from other devices live. The first load and a weekly full read (`LW_DELTA_FULL_EVERY_MS`) read everything; a local write shows at once (`lwRecordAnswer`, `lwSetDoc`/`lwDeleteDoc` and `lwDeleteProgressForWords` patch the watcher's cache), and a `count()` 3 s after load re-reads everything if the numbers disagree (docs deleted, or a lesson unpublished, aren't "changed since"). Only server timestamps move the cursor; an older plain-number `updatedAt` (lessons saved before) is kept but never queried. Each query needs its composite index (`firestore.indexes.json`); without it the watcher falls back to a plain listener on the whole query. Docs written before FSRS have a Leitner `box` instead of `stability`/`difficulty`. `lwCardMemory` reads them as stability = the box interval (10 min, 1, 3, 7, 14, 30 d) and raises the difficulty per lapse. The next answer rewrites the doc in FSRS form and drops `box`, so there is no migration script. It sits in a separate collection because users can't write shared words. `activity/{uid}_{YYYY-MM-DD}` for English and `activity/{uid}_{lang}_{YYYY-MM-DD}` for other languages (device-local date, `lwActivityRef`) store `{userId, lang, date, answers, correct, xp, goalMet, ms, updatedAt}`; the rules accept both id forms. Both are written together by `lwRecordAnswer` (one batch, `merge` + `increment`, no transaction). Every activity write (`lwRecordAnswer`, `lwAddPracticeTime`, `lwAddBonusXp`) goes through `lwActivityWrite`, which adds server `updatedAt` and shows the new counters at once (`lwBumpLocalDoc` on the watcher's cache), because `App` gets activity from `lwWatchActivity` (`lwWatchSince`); days written before `updatedAt` are read once and kept. Total XP is the sum of `activity.xp` of the current language. The daily goal is `users/{uid}.dailyGoal` (`dailyGoal_ro` for Romanian), default 20 answers.
- Reading texts: `texts/{id}` holds the meta (`title, author, level, source, chapters: [{title, words}], wordCount`, plus `userId/shared` like words, and only admins publish `shared` books). The body is in `texts/{id}/chapters/{n}` as `{userId, shared, title, paragraphs}`, so lists load without text. Books from `make-book` add `exercises: {questions, fill, bank, dialogue}` to a chapter (gaps marked `[[word]]`; meta chapters get `practice: true`). The reader then shows Chapter practice (`ChapterPracticeMenu`/`ChapterPractice` in `app.jsx`) after the chapter's last page and behind the Practice button: comprehension questions, typed gaps, a word bank in the text, and a dialogue where partner lines are spoken and the learner says their line with the gap (`lwListenOnce` + `lwMatchSpoken`, or types the word). Every answer goes through `recordAnswer` with mode `reading`, to the user's card for that word when `lwFindCardForClip` finds one, else activity only. `reading_progress/{uid}_{textId}` stores `{chapter, page, pct}` plus `practice.{chapter}.{kind}` (last score, %). Words added from the reader go to the user's "From reading" group (created on first use) with the book sentence as the example, and they are always private.
- Collocations: `collocations/{id}` stores `{word, key, pos, pattern, phrases: [{wordId, partner}], wrong: [{partner, fix}]}` plus `userId/username/shared` like words. The phrases are ordinary word cards. The entry only links them by id, and `partner` is the chip text in the game. Phrase text, translation and example are always read from the card, so a deleted card drops out of the entry (`lwCollocLive`). New phrases added in the form become cards in the user's auto group "Collocations" (shared for admins, whose entries are shared and link only shared cards). The game (`CollocView`) plays entries with ≥2 live phrases and ≥1 wrong partner (`lwCollocPick`). A right chip is Know for its card, a wrong chip is Again for every right phrase not found yet, and Hint is Again for the hinted one. Each card gets at most one answer per round. Gemini (`lwAiSuggestCollocations`) runs only from the form's "Suggest with AI". `recordAnswer` tracks answers sent today in a ref, so several answers in one tick award the goal bonus once.
- Grammar lessons: `lessons/{id}` are shared content written only by admins: `{title, topic, level, order, minutes, compare, published, focus, formulas, compareTable: {rows, tip}, examples, quiz}`. Text fields use `[[...]]` for highlights. `quiz` always has exactly 10 tasks (`LW_LESSON_TASKS`, enforced by the rules and `lwNormTask`): `{type: 'choice', q, options[4], answer, why}` or `{type: 'fill', q, answers[], why}`. Users read only published lessons (query `published == true`). Admins see drafts. Lessons come from `lwWatchLessons` via `lwWatchSince` (see progress below): `lwSetDoc` stamps a lesson with server `updatedAt`, and console scripts that write lessons set `updatedAt: window.lwServerTime()`. `lesson_progress/{uid}_{lessonId}` stores `{studiedAt, attempts, last, best, completedAt, saved, srs}`. In a topic, lessons are ordered by `order`, and a lesson opens once the previous one is completed (`lwLessonStatus`: locked/new/studied/completed). The test unlocks after "I've studied this". Tasks and options are shuffled per attempt. Only 10/10 completes a lesson and gives a one-time +50 XP (`lwAddBonusXp`). Completion also schedules the lesson's rule for spaced review: `srs = {stability, difficulty, due, lastReview, reps, lapses}` (FSRS via `lwNextLessonSrs`, which wraps `lwNextProgress` with a set grade). Grammar → Review (`GrammarReview`, `#/grammar/review`) plays `LW_GRAMMAR_REVIEW_TASKS` (2) random test tasks from each of up to `LW_GRAMMAR_REVIEW_LESSONS` (5) due lessons, mixed; `lwLessonReviewQueue` orders them by lowest chance to recall, and lessons completed before reviews existed (no `srs`) count as due, oldest first. When a lesson's tasks in the session are answered, `gradeLessonReview` in `App` saves its next `srs`: all right = Good, some = Hard, none = Again. The due count shows on Grammar's home card and in the drawer (`stats.grammarDue`). Each test answer goes through `recordAnswer(null, …)`, which writes activity only (`lwRecordAnswer` with `progress: null`). Gemini helpers are `lwAiGenerateLesson` and `lwAiRegenerateTask`. Starter lessons come from `scripts/seed-lessons.mjs`, run from the browser console as an admin.
- Badges: `LW_BADGES` (`progress.ts`) are 23 achievements (streak, daily goal, answers, words, time, level, reading, grammar, collocations). They are computed on the device from the current language's data (`lwBadgeMetrics`; the streak badge uses the best streak ever, `lwBestStreak`). `App` saves newly reached ones as `users/{uid}.badges.<id> = ms` (`badges_<lang>` for non-English) 2 s after the data settles and shows a toast. The first time, it saves quietly with one summary toast. Earned badges stay earned. `BadgesSection` in Profile shows them.
- Level test: `LevelTestScreen` (screen `leveltest`, opened from the level card in Profile) is one engine for every language. Questions come from `level_questions` (`{lang, level, skill, q, options[4], answer, why}`): shared content that only admins write, edited in-app through `LevelQuestionsAdmin`, with starter banks of 60 per language in `scripts/seed-level-questions.mjs`. The test asks 20 questions on a staircase (`lwLevelTestPick`): right moves one level up, wrong or "I don't know" one level down, and no question repeats. The result (`lwLevelTestResult`) is the rounded mean staircase step of the last 10 answers, one step lower if fewer than half at that level were right. It is saved as `users.levelTest` (`levelTest_<lang>`) and, if the user agrees, as their CEFR level. It gives no XP. The test is offered once a language has at least 30 questions.
- Video clips: `clips/{id}` (`{lang, videoId, start, end, quote, word, key, wordTr, ipa, pos, quoteTr, scene}`) are shared content that only admins write, edited in Learn → Video → Manage clips (`ClipsAdmin`, `ClipForm`). The quote marks the word or phrase as `[[…]]` (`lwSplitQuote`). A fragment is at most 60 s. `YouTubeClip` (`components.jsx`) wraps the YouTube IFrame API: it loads once, plays `start`→`end` and rewinds, and offers replay, speed and `onError` for removed or non-embeddable videos. `free` mode gives the full video with YouTube's controls for picking times. A clip belongs to a word, not a card: `lwFindCardForClip` finds the user's card by the same text (any form for single words), and answers in `VideoView` (Flip with Again/Know, or Type) go to that card's review progress. Without a card they give only XP and the daily goal, plus "Add to cards" into the auto group "From video". Session order is `lwClipPick`. Library word cards with a clip show a ▶ Clip button (`ClipModal`).
- Speech: every spoken text goes through `lwUtterance(text, rateMul)` in `data.js`, used by `lwSpeak` and the reader's read-aloud. It uses the device's best voice for the current language (`lwLangVoices`, ranked by `lwVoiceScore`) or the one picked in Profile (`VoicePicker`), plus Slow/Normal speed. Both are stored on the device in `LW_KEYS.voice`. A missing voice falls back to auto. When the device has voices but none for the current language, `lwUtterance` dispatches `lw-missing-voice` and `App` shows a toast once per language and session (otherwise the browser silently reads with its default English voice).
- Romanian transcription: `lwRoIpa(text, pos)` (`data.js`) builds a broad IPA transcription by spelling rules, without stress. `lwSetDoc` fills `ipa` with it for any Romanian word saved without one.
- Pronunciation: `PronunciationCheck` (components.jsx) uses the browser's SpeechRecognition and is hidden when the browser doesn't support it. It compares the transcript with the target text by longest common subsequence (`lwMatchSpoken`). Reading time goes into `activity.ms` through `lwAddPracticeTime`, every 30 s while a text is open, the page is visible and the user was active in the last minute. It adds no answers or XP.
- The rules define an `ai_usage` collection meant to be written by a Cloud Function, but no functions code exists in this repo.

**State flow in `App`**
- Auth state → user doc → live subscriptions to groups and words. All data lives in `App` state and reaches the views as props.
- `App` also subscribes to `progress` and `activity` and owns `recordAnswer(wordId, known, mode, opts)`. Study, Fill, Choice, Forms and Review call it on every answer except skip. FSRS grades: Again = 1, Choice right = Hard (recognition only), other right answers = Good, and Fill or Forms with `opts.easy` = Easy (`lwAnswerGrade`). Again brings the word back in 10 min (`LW_RELEARN_MS`). Otherwise the next review is set where the chance to recall falls to `srs.retention` (85/90/95%, default 90%), with ts-fsrs' fuzz seeded by word id and reps, at 04:00 local time on that study day. Know on a word that isn't due yet, on the same study day as its last review, changes nothing, so a word can't be ground to Mastered in one evening. A word is Mastered at stability ≥ 30 days (`LW_MASTERED_DAYS`). `App` calls `lwSetSrsSettings` while rendering, so the Again/Know labels (`AnswerButtons`) use the same retention. Review (`ReviewView`) plays `reviewPlan` from `lwReviewQueue`, ordered by lowest chance to recall first. It has two scopes, stored in `LW_KEYS.reviewScope` and switched in the Learn header. Focus (the default) plays due words of the groups selected in Learn, and `srs.background` (0/10/20%) of the first session goes to the most at-risk due words from other groups. All plays every due word. Words of paused groups (Library → Groups → Pause reviews; a paused group pauses its subgroups) never come up and aren't counted. A session holds at most `srs.session` words (20/50/100/All), and "Continue" loads the next one. The Review badge (`stats.dueCount`) is the size of the next session. Review settings live in Profile → Learning. Choice (`ChoiceView`) and Fill (`FillView`) play the selected groups shuffled but only new or due words (a missed word is re-queued for the round); "Practise all anyway" ignores the schedule. Like Cards, they report "N / M known" for the round to the Learn header (`onStatsChange`).
- Device-only settings (theme, selected groups, study direction, last batch of reading cards, the user's **personal Gemini API key**) persist in localStorage under the versioned `lw_*_v1` keys.
- Long-running AI jobs (reading-text generation, AI fill on import) run as promises owned by `App` (`startReadingGeneration`, `startImportAiFill`), so they survive tab switches. Results come back as toasts. `genIdRef` discards stale responses.
- Gemini is called straight from the browser with the user's own key. AI helpers throw errors whose `.code` is `no-key`, `bad-key`, `quota`, `refusal` or `network`, and `views/shared.jsx` maps those codes to messages (`LW_READING_ERROR_MSG`, `LW_IMPORT_ERROR_MSG`).
